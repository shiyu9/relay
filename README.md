# relay

セッション間の引き継ぎリレー。Claude Code の会話ログ（transcript）から**日記**（セッションごとの記録）・**ナレッジ**（永続知見）・**現在地**を自動で書き起こし、次のセッション開始時に注入するプラグイン。

A session-to-session handoff relay for Claude Code. It turns each transcript into a **diary** entry, distils durable **knowledge** and a single **current** page, and injects them back at the start of the next session.

**`claude` CLI があれば、記録はセッションが閉じたときに終わります。**次に開いたときには `current.md` が最新です。CLI が無い環境でも記録は失われず、次の起動でセッション自身が書き起こします（1セッション分だけ遅れます）。

Recording finishes as the session closes when a `claude` CLI is present, so the next session opens with an up-to-date **current** page. Without one, nothing is lost — the next session writes it up itself, one session behind.

## 仕組み / How it works

### 1 transcript = 1 日記エントリ

日記のエントリは**そのセッション自身の日付**のファイルに置かれ、見出しに時間帯とセッション ID を持つ。

```
diary/2026-08-27.md

## S1 19:11-22:30 (124c52dd)
### done
- 実際に達成したこと
### decisions
- 下した判断とその理由
### mistakes
- 誤り・手戻り
### handoff
- 次のセッションに要ること
```

日付をまたいだセッションは、またいだ日数が終了時刻に付く（`## S2 08:14-08:13+3d (00cb0081)` は 8/26 08:14 から 8/29 08:13 まで）。

同一性が ID で決まるので、**同じセッションを二重に記録しない。**resume で transcript が伸びたときは、新しい要約でそのエントリを**丸ごと差し替える**（追記して2つに分かれることがない）。

**中身の無かったセッションにも印だけ残る。**

```
## S3 00:29-00:34 (0846e4a6)
（記録するものがなかったセッション）
```

未記録かどうかは日記だけを見て決めているので、「読んだが書くことが無かった」を書き残さないと、そのセッションは永久に候補に挙がり続ける（実際に起きた）。この印は注入には出ない——空のセッションが引き継ぎの5枠を食わないため。

**relay 側に「何日前まで」という動く窓は無い。**Claude Code が `cleanupPeriodDays`（既定30日）で transcript を消すので、残っているものはすべて記録の対象になる。

ただし**導入した時点で一度だけ線を引く**（epoch）。その時点より前に終わっていた transcript は「記録済み」として扱い、遡らない。relay は既に数週間分の履歴を抱えたプロジェクトへ入るので、これが無いと導入のたびに全履歴の要約代を払うことになる（実測: 12プロジェクトで計86件・約394MB）。

線は `~/.claude/relay/epoch/<プロジェクト>` に ISO 日時のテキスト1行で置かれ、**プロジェクトごとに1回だけ書かれて二度と動かない。**動く線は保持の窓と同じで、「昨日は窓の中だったものが今日は外」という取りこぼしが生まれる。一度きりの線には外側が無い。

- 比べるのは transcript の**末尾**の時刻なので、線を引いた時点でまだ走っていたセッションも、あとで resume して伸びたセッションも、普通に記録される
- 線を動かしたいときは**そのファイルを編集する**（消すと次の起動で現在時刻に引き直されてしまう）。日付だけ（`2026-08-20`）でもよい
- ファイルの中身が日付として読めないときは、**線が無いものとして全件を候補に戻す。**打ち間違いで記録が黙って消えるより、候補が溢れて見えるほうがよい

### 記録はセッションが閉じたときに走る

**`claude` CLI がある環境では、記録は SessionEnd で終わる。**次に開いたセッションには、前回までが入った `knowledge/current.md` が最初から渡される。

CLI が無い環境では SessionEnd は印だけを置き、**次の起動が拾う**。記録が失われることはなく、`current.md` が1セッション分だけ遅れる。

```
セッションを閉じる
  └ SessionEnd（20ms で終わる）
      ├ 終了印を置く
      └ 録音係を起動して、すぐ抜ける ── claude -p が記録し、relay_apply が書く
                                          （数分。次のセッションは待たされない）
```

### 3つのフックと、1つのスキル

- **SessionEnd** — 終了印を置き、録音係を1つ起動して、ログを1行書いて終わる。**このフックは1.5秒しか持たない**（後述）ので、それ以上のことは何もしない
  - 録音係は**親を `explorer.exe` に付け替えて**起動する。フックが時間切れになると、そのプロセス木が辿られて子孫ごと殺されるため。付け替えた子はその木にいない
  - CLI が無ければ録音係は起動せず、終了印だけが残る
- **SessionStart**（新規起動・`/clear` 後のみ）
  - `knowledge/pitfalls.md` `workflow.md` `decided.md`、**日記の直近5エントリ**、`tasks.md` の未完タスク、`knowledge/current.md` をこの順に注入する（変わりにくいものから変わりやすいものへ）
  - **前のセッションを記録中なら、そう伝える。**注入した `current.md` にその分がまだ入っていないことを明示し、「そのセッションに関わる判断は未確認として扱う」と添える。黙って古いページを渡さない
  - 未記録の transcript が残っていれば（SessionEnd が発火しなかった、CLI が無い、録音係が落ちた）、**まずユーザーに1行伝えてから**記録する手順を渡す。数分かかる作業を、何も言わずに始めない:
    1. 記録ジョブ（transcript 1本につき1回・最大3本）をサブエージェントで実行。**3本は互いに独立なのでまとめて呼ぶ**
    2. `relay_apply.py` が結果をファイルへ反映し、要約を1行返す
    3. 日記が書かれていれば「現在地・見送り・タスクの消し込み」ジョブを実行して再度反映
    4. 要約行の `merge_due` が `yes` なら統合ジョブを実行して再度反映

    **統合ジョブは項目を削除しない。**重複を1行にまとめ、矛盾を新しい `[日付]` に合わせるだけで、行数のために削ることはしない。80行はそこが育ったという合図で、超えたときは「別ファイルへ移してよさそうな項目」を理由付きで挙げ、**その候補は日記に書かれる**（移すかどうか、どこへ移すかは人が決める）。

    発火条件は Python が計算する。**行数が上限を超えていて、かつ前回の統合から中身が変わっている**ときだけ `merge_due=yes` になる（削除しない以上、行数だけを条件にすると大きいプロジェクトで毎回発火し続けるため）。

    統合は2ファイルを全文で置き換えるため、`relay_apply.py` は**ジョブが作られたときの本文と現在のファイルが一致するときだけ**適用する（一致しなければ飛ばし、要約行に `stale=1` を出す）。手順1が同じファイルに追記するので、ジョブは反映のたびに作り直される。
  - **ジョブの本文はファイルに置かれ、サブエージェントだけが読む。**本体のコンテキストには数行の手順しか入らない
- **UserPromptSubmit** — **起動時に記録中だったセッションの記録が終わったときだけ**、1行だけ伝える。1セッションに最大1回で、それ以外は完全に無言

**relay がセッションの途中で口を出すのは、この最後の1回だけ。**起動時に「`current.md` はまだ古い」と断った以上、それが終わったことを言わなければ、読み手は正しくなったページを疑い続けるか、断り書きを忘れて古いものを信じることになる。判定は2回の `stat` で済み、transcript は走査しない。

### なぜ SessionEnd が1.5秒しか持たないのか

Claude Code は、hook が `timeout` を超えるとその**プロセス木を辿って子孫ごと殺す**。時間内に終われば何も殺さない。そして**プラグインの `hooks.json` に書いた `timeout` は無視される**（5 でも 30 でも既定の 1500ms のまま。同じ書き方を `settings.json` に置くと効く）。

relay はプラグインとして配信されるので、**猶予を自分で買えない。**だから SessionEnd は「印を置き、1つ起動し、1行書く」だけにしてある（実測 20ms）。録音係の親を付け替えるのは、ウイルス対策が `python.exe` の起動をスキャンするような、relay の側では防げない理由で上限を超えたときの保険。

（Windows・CLI 2.1.252 で 42 セッション分を実測。終了経路 — `/exit`・Ctrl+C・窓を閉じる — による差は出なかった）

### `/relay:record` — いま記録する

閉じるのを待たずに、その場で記録を走らせるスキル。CLI が無い環境や、記録が落ちたときの手動の受け皿にもなる。

起動時の記録と違うのは1点だけ、**いま動いているセッション自身も対象に入る**こと。通常の判定は「SessionEnd の印がある、または30分以上更新なし」なので、走行中のセッションは絶対に対象になりません。

自分を見分けるために、スキルは毎回新しいトークンを作ってコマンドに載せます。**ツール呼び出しは実行される前に transcript へ書かれる**ので、スクリプトは自分が書き込まれているファイルを名指しできます。

- **一致が1本でなければ記録しない。**0本でも2本以上でも「特定できませんでした」と言って止まります。2本目を切り捨てて新しいほうを採ると、**別のウィンドウで進行中のセッションを途中で要約する**ことになるためです
- 自分の特定に失敗しても、**他に未記録があればそちらは記録します**
- 自分を記録したあとにセッションを続けた場合、日記はその時点までの内容になります。次の起動でエントリごと差し替わるので、放っておいて構いません

### ファイル

| ファイル | 性質 | 誰が書くか |
|---|---|---|
| `diary/YYYY-MM-DD.md` | セッションごとの記録。エントリ単位で差し替え | relay |
| `knowledge/pitfalls.md` | 技術的な罠と回避策。追記＋重複の統合（削除はしない） | relay |
| `knowledge/workflow.md` | このユーザーとの進め方の学び。追記＋重複の統合（削除はしない） | relay |
| `knowledge/current.md` | **現在地**。1つの節・毎回上書き・行数の上限なし | relay |
| `knowledge/decided.md` | 見送った案と**再開条件**。毎回上書き・剪定あり | relay |
| `tasks.md` | 未完のタスク。**relay は完了したものを消すだけ** | セッション（消すのは relay） |

`current.md` と `decided.md` は**レコーダーが唯一の書き手**で、セッション中に手で編集しない（次の記録で上書きされる）。`decided.md` から落ちた項目は、Python がその日の日記に記録するので**消えた理由をあとから追える**。

### `tasks.md` — 完了したタスクを消す

`tasks.md` だけは relay の持ち物ではない。**項目を足すのはセッション自身**で、relay がするのは「日記の `done` が完了したと言っているタスクを消す」ことだけ。追加は既にどのプロジェクトでも回っており、壊れているのは消し込みの側だから。

- 見るのは `- [ ]` で始まる行だけ（続きのインデント行も1項目として扱う）。**書式は強制しない**——見出しの立て方も優先度の付け方も、そのプロジェクトのまま
- 消す根拠は**その回に確定した日記の `done`** に限る。日記が「やった」と書いていないものは消えない
- 消す前に Python が `tasks.md` 上での実在を確かめる。**逐語で一致した行だけが消える**ので、言い換えや切り詰めでは何も起きない
- 消した項目は続きの行ごと**その日の日記**（`## relay: 完了として tasks.md から消した項目`）に残るので、消し間違いは戻せる
- 消し込みは記録と同じ回に走る。新しいフックは増えない代わり、**完了からファイルが変わるまでに1ターンの遅れがある**

**ファイルへの書き込みはすべて Python が決定的に行う。**サブエージェントは区切り付きのテキストを一時ファイルへ出すだけで、日記もナレッジも直接触らない（安価なモデルに追記を任せて既存エントリを消失させた実バグがある）。

```
/plugin marketplace add shiyu9/relay

```

## 設定 / Configuration (env)

| 変数 | 既定 | 意味 |
|---|---|---|
| `RELAY_SCOPE` | (なし=全プロジェクト) | このパス配下のプロジェクトだけで動作 |
| `RELAY_DISABLED` | - | `1` でそのプロジェクト無効（`.claude/settings.json` の `env` に設定） |
| `RELAY_MODEL` | `claude-haiku-4-5` | 記録のサブエージェントに指定するモデル |
| `RELAY_MIN_USER_MSGS` | `3` | これ未満のユーザー発言数のセッションは記録しない |
| `RELAY_EPOCH` | (なし=ファイルの線を使う) | 導入時点の線を上書き。ISO 日付/日時で指定、`none` で線を無効化（全履歴を候補に戻す）。ファイルには書き込まない |
| `RELAY_KEEP_API_KEY` | - | `1` で録音係の環境に `ANTHROPIC_API_KEY` を残す。既定では**外す**（下記） |

例: 特定フォルダ配下だけで使う（ユーザー settings.json）

```json
{ "env": { "RELAY_SCOPE": "C:\\claude-projects" } }
```

### 任意: thinking summary を記録に活かす

`~/.claude/settings.json` に `"showThinkingSummaries": true` を入れると（`/config` からは設定できません）、Claude Code が API に `thinking.display: "summarized"` を要求し、thinking の中身が transcript に残るようになります。relay はそれを **decisions**（捨てた案・検討過程）と **mistakes**（なぜ誤った判断をしたか）の根拠に使います。`done` / `handoff` には効きません。

```json
{ "showThinkingSummaries": true }
```

- 表示が変わるだけで、thinking トークンの消費＝課金は変わりません。
- `false`（既定）でも relay は全機能そのまま動きます。transcript の thinking が空なら、記録係はそれを使わないだけです。

## 注意 / Notes

- **録音係は既定でサブスク認証で走ります。**環境から `ANTHROPIC_API_KEY` を外してから起動するため。このキーは公式仕様上サブスクより優先され、無効なキーが残った環境では録音係が 401 で黙って死にます（実際に起きた事故です）。API キー認証しか使えない場合は `RELAY_KEEP_API_KEY=1` を設定してください
- **録音係を動かすと、不可視のコンソールプロセス（`conhost.exe`）が数個生えます。**`claude` が内部で bash を起こすためで、避けられません。**窓は出ません**（実測: 0.5秒ごとに監視して、可視のトップレベル窓はゼロ）。タスクマネージャで見えるのはそのためです
- **記録中に新しいセッションを開いても待たされません。**録音係は別プロセスで走っています。ただしその数分間だけ `current.md` は前のセッション分を含まないので、起動時にその旨が伝えられ、終わったときにもう一度伝えられます
- **同じプロジェクトの録音係は同時に1つだけ走ります。**2本が並行して `current.md` を書くと後から終わったほうが勝ってしまうため。2本目は最大10分待ち、それを過ぎたら次の起動に任せます
- **導入した時点より前の transcript は遡りません**（上記の epoch）。導入後に終わったセッションから記録が始まります。1回の起動につき最大3本なので、溜まった場合は数回の起動をかけて埋まります。それぞれのエントリは**そのセッション自身の日付**のファイルに入るので、当日の日記に過去がまとめて流れ込むことはありません。
- **線は「取りこぼし」と「backlog」を区別しません。**導入の直前に閉じた未記録のセッションも、線より前なら記録されません。それらが必要なら `~/.claude/relay/epoch/<プロジェクト>` を古い日付へ書き換えてください。
- 記録はセッション開始時に走るため、**起動が少し待たされます。**その代わり、ヘッドレスの `claude` CLI が使えない環境でも動きます。
- サブエージェントは中間結果を `~/.claude/relay/inbox/` に書きます。プロジェクト外への書き込みなので、環境によっては許可を求められます。毎回聞かれるのが煩わしい場合は settings.json の `permissions.allow` に `Write(//<ホーム>/.claude/relay/**)` を足してください。
- **auto mode では、記録ジョブの呼び出しが分類器に拒否されることがあります**（`Blocked by classifier`）。手順は拒否されたジョブを再送せず次の起動へ回すので、記録は失われません。注入される呼び出し文は、目的・手順・書き込む1ファイルを明示した形にしてあります。
- **日記のファイルを手で消すと、その範囲が次の起動で記録し直されます**（未記録かどうかを日記そのものから判定しているため）。
- 記録は transcript が残っている間だけ可能です。`cleanupPeriodDays`（既定30日）を過ぎた分は遡れません。
- **Windows でのみ動作検証済み**です。コードは macOS/Linux を考慮していますが未検証です。/ Only tested on Windows; macOS/Linux paths exist in code but are unverified.
- 実行ログ: `~/.claude/relay/log.txt`
